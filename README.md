# Telegram-бот для заполнения договоров РАО и ВОИС

Бот работает в личном чате. Он принимает реквизиты в виде строк «Поле: значение», запоминает корректные ответы и отправляет заполненный DOCX. В проекте настроен один демонстрационный договор с условным текстом. Чтобы использовать формы РАО и ВОИС, добавьте рабочие копии своих договоров по инструкции ниже.

## Получите токен

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте команду `/newbot`.
2. Введите отображаемое имя бота, затем придумайте уникальное имя пользователя с окончанием `bot`.
3. Скопируйте токен из ответа BotFather. Сохраните его только в локальном файле `.env`.

## Запустите на компьютере

Установите Python 3.10 или новее. Распакуйте архив и откройте терминал в каталоге с `bot.py`.

macOS или Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В редакторе впишите токен после `BOT_TOKEN=` в файле `.env`. Затем выполните одну из команд.

```bash
# macOS / Linux
.venv/bin/python bot.py
```

```powershell
# Windows
.\.venv\Scripts\python.exe bot.py
```

Откройте личный чат со своим ботом, отправьте `/start` и выберите договор. Замените примеры в заготовке и отправьте её. Строки можно переставлять. Если осталось одно поле, можно отправить его значение отдельным сообщением. Для завершения работы нажмите Ctrl+C в терминале.

Реквизиты хранятся в памяти текущего процесса отдельно для каждой пары «пользователь и чат». После успешной отправки состояние формы очищается, а после перезапуска незавершённые формы исчезают. DOCX собирается в памяти, поэтому временных файлов на диске нет. Логи приложения отключены, в консоли выводится статус запуска. Переписка и отправленные файлы остаются в чате Telegram.

## Добавьте свой договор

1. Создайте в Word копию исходного договора. Сохраните её в папке `templates`, например под именем `vois-venue.docx`.
2. В копии замените переменный текст на плейсхолдеры вида `{{ inn }}`, `{{ contract_number }}` и `{{ contract_date }}`. Используйте тот же ключ для каждого повторения одного реквизита. Проверьте основной текст, ячейки таблиц и верхние и нижние колонтитулы всех разделов. Для каждого плейсхолдера наберите его целиком с единым форматированием, унаследованным от заменяемого текста.
3. Добавьте объект в массив `templates` файла `contracts.json`. В примере ниже указан один реквизит. Перечислите в `fields` все обязательные поля вашего DOCX.
 
```json
{
  "id": "vois-venue",
  "group": "ВОИС",
  "title": "Договор ВОИС для площадки",
  "file": "templates/vois-venue.docx",
  "fields": [
    {"key": "inn", "label": "ИНН", "type": "inn", "example": "1234567890"}
  ]
}
```

4. Для каждого пункта используйте уникальный `id` из строчных латинских букв, цифр, дефисов или подчёркиваний. Значение `group` должно быть `РАО` или `ВОИС`. `key` совпадает с именем внутри плейсхолдера. `label` отображается в заготовке и должен быть уникальным в пределах договора. Для `type` доступны `text`, `inn` (10 или 12 цифр) и `date` (существующая календарная дата в формате ДД.ММ.ГГГГ). `example` задаёт тестовое значение для заготовки. Удалите объект с `id` `demo`, чтобы убрать образец из меню.
5. Перезапустите бота. При запуске он сверяет ключи конфигурации с плейсхолдерами в DOCX. Если количество шаблонов больше `group_menu_threshold`, бот сначала показывает доступные группы. Заполните тестовый экземпляр и проверьте в Word все повторяющиеся поля, колонтитулы и переносы строк с длинными значениями.

## Проверьте генерацию без токена

Из каталога проекта запустите скрипт тем же интерпретатором, которым запускаете бота.

```bash
python check_docx.py demo filled-demo.docx
```

Скрипт подставляет примеры из конфигурации, открывает полученный файл через python-docx и сохраняет его для проверки в Word. Можно указать любой настроенный `id`.

## Карточка компании

После выбора договора можно прислать реквизиты одним текстовым сообщением или приложить DOCX до 5 МБ. В DOCX читаются абзацы и строки таблиц. В каждой строке таблицы удобно размещать название поля и значение в соседних ячейках.

Порядок полей свободный. Поддерживаются полные названия из конфигурации и распространённые сокращения, например «юр. адрес», «р/с», «к/с», «БИК», «ОГРН» и «ИНН/КПП». Между названием и значением можно поставить двоеточие, знак равенства или пробел. Адрес может продолжаться на следующей строке. При двух разных значениях одного поля бот запросит уточнение. Ранее принятые значения сохраняются.

Юридический, фактический и почтовый адреса распознаются раздельно. В договоре ВОИС для радио предусмотрены юридический и почтовый адреса. Чтобы использовать фактический адрес, добавьте в нужное место DOCX плейсхолдер `{{ user_actual_address }}` и соответствующее поле в contracts.json. Реквизиты из карточки компании относятся к пользователю договора. Поля ВОИС заполняются по их полным названиям.

Для новых вариантов названия добавьте в описание поля необязательный массив `"aliases": ["Ваше название", "Ещё одно название"]`. Доступны типы проверки `ogrn` (13 или 15 цифр), `kpp` (9), `account` (20) и `bic` (9), а также прежние `inn`, `date` и `text`. Проверка количества цифр не подтверждает существование организации или банковского счёта.

Пример сообщения

```text
БИК 044525225
Почтовый адрес: г. Москва, а/я 15
Полное наименование: ООО «Пример»
ОГРН: 1234567890123
ИНН/КПП: 1234567890/123456789
Банк: ПАО Сбербанк
р/с: 40702810900000000001
к/с: 30101810400000000225
Юридический адрес: 123100, г. Москва,
ул. Примерная, д. 1
```

Номер и дата договора, сведения о подписанте и другие недостающие обязательные поля будут запрошены отдельно.
